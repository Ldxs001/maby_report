# 《本征》的方法论沉淀：为什么会烂——三种不报警的腐坏

> 内容不是「旧了才失效」，从写下的那一刻起就在腐坏。腐坏有三种形态：路径断掉（失忆）、同等重要的东西堆过带宽（膨胀）、多处副本各改各的（副本漂移）。三种都不报警，所以靠「更小心」防不住，只能靠结构。本篇只讲病灶，治法只在机制层点到；工序在 02 到 09。
>

## §1 引子：写过、找不到、不敢信

接手一摊陌生的活，第一周往往会遇到三件小事。

第一件：明明有版本写过，翻了两小时没找到，最后重写了一遍。第二件：找到了三份，内容不一样，不知道哪份算数。第三件：一份很全的文档，从头读到尾，读到后面忘了前面，索性不读了。

三件事看起来是三种毛病：记性差、版本乱、文档长。往深一层看，它们是同一个东西的三个切面——**规则在传递过程中，以三种不同的方式失真，而且三种都不发出声音。**

这就是本篇要说的：腐坏不是「用久了变旧」，是**结构本身带的**。写下第一句话的时候，腐坏就已经开始了。

这一节的场景是经验刻画，不是特定事件的记录。三种形态的判定标准见 §2 到 §4。

## §2 腐坏一：失忆不是忘了，是路径断了

失忆有两种，价值完全不同。

**内容没了**：删了、丢了、覆盖了。这种好办——知道丢了什么，重写就行。

**路径没了**：内容还在，但检索不到它在哪，或者不知道该找它。这种难办，因为**当时那一轮不知道自己丢了东西**。

「找不到」多数属于第二种。记录只增不减，检索能力却不变。加到某个量级之后，每一份都还在，但从「能找」变成「碰运气」。

一个具体的机制：**索引比内容烂得快。** 内容写下来可以三年不动，指向它的那条路径——标题、目录、命名、口头交接——换一次上下文就断一次。索引断了，内容再多也等于不存在。

判据只有一条：**一个不共享当时上下文的接手方，在有限步数内能不能定位到它？** 说得出「在哪一类、叫什么、从哪进」，算找到；只能说「我记得在某处写过」，不算路径，算记忆。

失忆的隐蔽处在这里：它不产生错误，只产生重复。重写一遍的那份，往往比原来那份更差——因为重写的那一方看不到原来那份里有哪些坑已经踩过。

## §3 腐坏二：膨胀不是变多，是同等重要

带宽是硬的。超过的那部分不进决策，直接丢。

短时记忆一次能同时处理的单元在四个左右 [1]；模型的上下文窗口看起来很大，但放在中间位置的信息利用率低于首尾 [2]。数字不同；这里取的是结构上的相似，不是同一实测——**这是跨对象类比，不是推论**，只作旁证：一次能同时端住的东西有限。

[2] 那条结论还有一个更具体的形态，叫 **U 型注意力**：长上下文里，开头和结尾记得住，中间是盲区——越长的空，中间越盲。它解释了膨胀最隐蔽的一种后果：表面读完了，**中间没进**——一份长文档从头读到尾，取用者记住的只有开头定下的口径和结尾最新的要求，中间改过几轮的约定恰好落在盲区。治法也顺着这条机制：**多阶段分段**——把一次要读完的长文档切成几段，这套框架让每段各自从「开头」读起，把关键约定放在该段开头。分层与渐进加载（02 §5、09）就是这条机制的结构版：常驻层在结构上就是一份「开头」。

膨胀有两种写在字数上的形态。一种是条目变多：条目翻了近十倍。另一种是单条变长：一句话变成一段话，一段话变成一节。

还有第三种，它不体现在字数上，却让优先级整体失效：**「重要」这个词通胀了。**

一开始重要的只有几条，后来翻了约十倍，最后每一条都不敢删。条目数没超，但优先级失效了——因为全部同级，等于没有级。这时候取用者面对的是一份「什么都说了」的清单，实际能执行的是零。

一个可以算的后果：超过带宽之后，新增内容挤掉的是原来那几条的位置——净增有限，甚至为负。

判据同样是两条：**常驻的那一层，条目数有没有上限？单条有没有长度上限？** 两个上限都没有的清单，会一路长到读不完。

膨胀还有一个伪装：**它看起来像勤奋。** 加一条比删一条容易，写得全比写得准安全。于是每一轮修订都在加，减的成本高过收益——直到整份东西重到打不开。

## §4 腐坏三：副本漂移不是错，是结构不报错

同一句话，存在两处。改了一处，忘了另一处。

这一种腐坏的全名是**副本漂移**：漂移发生在多个副本之间——同一句话存在两处，各自被改，互不知情。02 会把「漂移」扩展成一个总机制（状态偏离锚，偏离量随距离增大）；本篇只讲它的副本形态。这是结构问题：**副本之间没有一致性检查。** 内容对不对，没有比对项；两处不一样，系统不报错。等到用的时候才发现口径打架，而这时候往往已经在两个地方各按各的做了半年。

漂移有三种：

| 形态 | 怎么发生 | 发现时的样子 |
|---|---|---|
| 版本漂移 | 改了一处，另一处还是旧的 | 两份都像真的，日期分不出先后 |
| 口径漂移 | 同一个词，两处定义不同 | 讨论半天，其实在说两件事 |
| 时效漂移 | 一处写了到期条件，另一处没写 | 一边已经作废，一边还在执行 |

三种里面，口径漂移不好查。因为它不表现为「不一致」，表现为「都说得通」。两个接手方各拿一份，各自逻辑自洽，吵起来才发现词义不同。

判据：**同一句话，有没有两个完整版？** 有，就是副本漂移的入口。注意是「完整版」——两处各写半句、互相指向，不算；两处都能独立读通，才算。

副本数量越多，不一致的概率越高，而且**除非把日期或作废标记写进去，副本不会自称旧的**。这是它比前两种腐坏更难防的地方：失忆在主动检索的那一刻还会撞上「找不到」——那是被动撞见，不是腐坏主动发出的预警（§5 表里的「信号＝无」说的是后者）；副本漂移连这种被动撞见都没有，两版各自读得通，不撞就不会发现。

## §5 三种腐坏的共同点：都不报警

把三种放在一起看，会发现一个共同结构。

| 腐坏 | 失败时的信号 | 接手方的感受 |
|---|---|---|
| 失忆 | 无 | 以为没有，其实有 |
| 膨胀 | 无 | 以为读了，其实漏了 |
| 漂移 | 无 | 以为一致，其实两版 |

三种都是**静默失败**：三种形态各自的失败信号一栏都是空的，而信号为空正是它们不能被「更认真」治好的原因。

写得越全——加速膨胀。多留一份备份——加速漂移。把东西记在当时的上下文里——加速失忆（那一段一关就没了）。

把三种放倒看，还有一个共同的根：**省事**。写进最近的地方最省事——所以副本越攒越多（漂移）；加一条比删一条省事——所以条目只增不减（膨胀）；记在当时的上下文里最省事——所以路径随上下文一起断（失忆）。省事本身不是错，错在体系没有让省事付一次代价。这套框架的意义就是收这笔费：每写一处，过一遍落点判定——它落哪层、归谁管、什么时候退。三次落笔各付一次判定的钱，三种腐坏就各慢一拍。

认真的方向由结构决定；方向错了，认真只是把腐坏推得更快。

所以后面这些做法，都不建立在「记住」「注意」「自觉」上。判据只有一条：**这条规矩失效的时候，有没有东西会红？** 红不了，它就只是一句愿望。

**一组对照**，取自本书的三处实例：

| 形态 | 现象 | 属哪种腐坏 |
|---|---|---|
| 正例 | 跨篇提另一篇时写篇号（09a、08b），不写「前文」 | 路径可定位：换个接手方也能顺着编号找到 |
| 反例 | 一批引用表把出处写成书外的路径，取用者手里没有那份东西 | 失忆：内容在别处，路径指向书外 |
| 半例 | 一批摘要里并列七个对照名字，结语写「六个」 | 漂移：名字在、数量没对齐，两处各自都读得通 |

正例说明「编号即路径」；反例说明路径必须以取用者手上的东西为准，指向书外的路径等于没有路径；半例说明漂移最会伪装——两处都自洽，只差一个数。

这三种形态是经验刻画：删掉的能重写，路径断的只能猜目录，副本分叉的两版各自读得通——三种都不报错，也不按出现次数统计。

## §6 反直觉：越完整，烂得越快

到这里可以推出一个不太舒服的结论。

「记得越全越好」是一个直觉，它在小规模下成立，过了某个量级就反转：

- 越完整 → 条目越多 → 越过带宽 → 读不完 → 实际可用内容趋于零（膨胀转失忆）
- 越完整 → 备份越多 → 副本越多 → 不一致概率越高（膨胀转漂移）

完整是腐坏的加速器。这一句可以按上面两条机制逐项复算：条目加一条、读物多一份、副本多一版，各自的腐坏速度都在上升。

边界要说清：**少记会直接制造失忆**——该有的没有。这里主张的是**分层**：把「完整」放在不常用的低层，把「关键」压到常用的高层。完整留给检索，关键留给常驻层。

这一层区分是全书的地基：**腐坏治不了，只能分配。** 让每一层只承担它能承担的腐坏速度。

## §7 结语：一条判据管三种腐坏

三种腐坏，一条判据：

> **一个不共享当时上下文的接手方，在有限的时间与有限的步数内，能不能把这件事接住？**

- 接不住，因为找不到——失忆
- 接不住，因为太多——膨胀
- 接不住，因为不知道信哪份——副本漂移

三种失败形态，同一句问句。后面八篇讲的判、落、写、检、长、退，都是为了让这句问句的答案是「能」。
